# 业务规则

实现只认本文件。改规则时同步 Python、前端和测试。

## 1. 做什么

把气泡图 PDF 切开，分块交给 DeepSeek 识图，汇总成可核对的 JSON。核对后从 JSON 导出检查作业标准、控制计划、检查清单、特殊特性清单和全尺寸 FAI。

## 2. 不做什么

不当局域网服务：只绑 `127.0.0.1`。
不把整份 PDF 或整页一次送进模型。
不读材料工艺字典，不画工序树。条文、问题列表、图号、页码、特性表的视图/区域/位置不进表。

## 3. 切片规则

### 3.1 输入

只接受 PDF。主流程不读 PDF 正文：先光栅成页，再切成标题栏、技术要求条带、单个红色气泡。每个识图请求只带一块 PNG。

### 3.2 编号

- 模号：`LG-` 后接字母或数字（`LG-26554`、`LG-PT26500`）。优先从文件名取，标题栏再核对。
- 料号：`P` 后接数字（`P000005766001`）。
- 读不到的字段留空，写入问题列表，页面可手改客户、品名、模号、料号、图号、版本。

### 3.3 气泡

字段：`num`、`special`（`NA` / `SC` / `CC`）、`special_no`、`type`、`description`。
`type` 只能是 `尺寸` 或十四种形位公差中文名（直线度、平面度、圆度、圆柱度、线轮廓度、面轮廓度、平行度、垂直度、倾斜度、位置度、同轴度、对称度、圆跳动、全跳动）。
名义值、上限、下限由描述解析，不采用模型写的三个数字。

### 3.4 技术要求

分两条：条文（编号、正文、特殊特性）和特性表（CC/SC 号、名称、参数、视图、区域、位置）。
气泡上的 `SC 27` 要和特性表里的 `SC 27` 对上；对不上列入问题。

### 3.5 密钥

DeepSeek 密钥只从本机 `api-key.md` 读。不进 git、不写进日志、不出现在 API 响应里。
模型名 `deepseek-flash`，接口 `https://api.deepseek.com`。

### 3.6 导出

复制 `data/template` 里的 SIP、QCP Template、SIP Checklist A1、SC list 填格，并按尺寸检测报告表头新建全尺寸 FAI。不使用 `Control Plan控制计划_SL-32_04.xlsx`。不读 `dic.csv`。

- 表头：客户、品名、模号、料号、版本。品番、材质、模穴留空。图号不写。
- 全部气泡进 FAI（NA / SC / CC）。三列写 `std_val` / `max_val` / `min_val`。
- SC / CC 气泡再进 SIP、检查清单、控制计划的「尺寸检验」、特殊特性清单。NA 只留在 FAI。
- 特性表进 SIP 和检查清单。名称含「重量」的检查类为重量，其余为性能。检查项写名称，规格写参数。有 SC 或 CC 号的特性再进特殊特性清单。不进控制计划、FAI。无标识的特性不进特殊特性清单。
- 检查类顺序：重量、性能、尺寸。工具、频率、责任者、管控方法留空。SIP 尺寸行在成型列打点。
- 控制计划没有工序时只写一个过程 `P01` 尺寸检验。
